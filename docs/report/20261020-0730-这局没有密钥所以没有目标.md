## 一、这份日志说明什么

整局 88 秒，47565 个包，握手材料都齐了，但：

```
[dec] has_pub=true has_key=false has_gns=true dir=c2s frames=2000
      方案="" 已解帧=0 消息=0 玩家=0(来源=无) 最佳=无
```

`has_key=false` → 没有客户端私钥 → 派生不出会话密钥 → **一帧都没解密**。
所以 `[gnspos]` 没有数据可打 —— 上一轮把诊断行挂到 3 秒节拍上的修复
在这份日志里**根本没机会被执行**（那段代码在「解出明文之后」才会跑到）。

### 阻塞点

```

[key] hint 表为空（...hints.json），本次走全量扫描
```

`memscan.FindPid` 是**精确匹配**（`exe == want`，见
`internal/memscan/process.go:94`），所以 `vgc.exe` 确实在跑（pid 6256），
不是误报。Vanguard 是《无畏契约 / 英雄联盟》的内核级反作弊。

按硬规则 212，闸门在 `resolvePID()` 处一刀切：反作弊在场就**一点不碰** cs2.exe，
于是 keyfind 连进程句柄都拿不到。

## 二、附带暴露的三个日志问题（都已修）

### 1. 闸门只说「不许碰」，没说「所以这局没目标」

原来的 `warnACBlocked` 讲清了风险和处置，但**没有一句话说后果**。
用户看到满屏 `已解帧=0` 只会以为雷达坏了。

现在补两段：

```
   ⚠ 后果：这一局**不会有任何雷达目标**。
     没有会话私钥就解不出一帧，`[dec]` 会一直是 `已解帧=0 消息=0 玩家=0(来源=无)`，
     并且反复出现「GNS 握手材料已齐，但还没有客户端私钥」。
     那不是 bug，是这道闸门在起作用 —— 收包正常，解密没开始。
```

并按反作弊类型给**具体**处置（笼统说「换社区服」帮不上忙）：

```
   Vanguard 是《无畏契约 / 英雄联盟》的反作弊（vgc 服务），**不保护 cs2.exe**。
   如果你只是在玩 CS2、顺便开着那个游戏，按下面做就能恢复：
     ① 完全退出无畏契约 / 英雄联盟（不是最小化）；
     ② 管理员 PowerShell 执行 `sc stop vgc`（或重启一次电脑）；
     ③ 重开本工具，看到 `[dec] ... has_key=true` 就说明通了。
```

### 2. `off(未发现目标进程端口，不过滤)` 这句话在骗人

`startFilterLoop` 的 `refresh()` 里，`resolvePID()` 失败就 `return` ——
反作弊拦住时过滤器**永远不会生效**。但 `[stats]` 打的字是
「未发现目标进程端口」，看起来像「cs2.exe 没端口，等一下就好」。

实际是两件完全不同的事：
- cs2.exe 还没起来 → 等 20 秒就好；
- `resolvePID` 被闸门拦住 → **这一局永远不会过滤，也永远不会解密**。

现在 `filterOffWhy` 记下真实原因，`[stats]` 打的是：

```
off(反作弊在场（Vanguard (pid 6256)），已禁止访问游戏进程；换纯社区服再采，...，不过滤)
```

### 3. 两行日志刷屏，把有用的信息全冲掉

| `[room1] GNS 握手材料已齐，但还没有客户端私钥` | 每次 `tryGNS` 都打（88 秒里上百遍） | 只打一次，且补上「这一局解不出任何一帧」 |

## 三、这局还有两条值得记下的观察

### 有两条大流量，握手只在小的那条上

```
[stats] 收 47565 包｜c2s 35211 s2c 12354
        最忙端口 3477(40066) 59852(40064) 17017(6622) 58653(6597)

[event] handshake_found ... dst_port:17017 src_port:58653
[event] server_hello   112.45.46.209:17017 → 10.134.209.48:58653
```

`3477↔59852` 有 40066 个包（88 秒 ≈ 455 包/秒），但握手是在
`17017↔58653` 上抓到的（6622 个包）。**两条都是 UDP、都像游戏流量。**

如果游戏主链路是 3477 那条，说明它的握手在我们启动之前就完成了 ——
那样这一局即使没有反作弊也拿不到私钥。这条要等有密钥的样本才能确认。

### `c2s` 是 `s2c` 的 2.8 倍，不正常

正常对局服务端下发的包应当不少于客户端上行。`c2s 35211 / s2c 12354`
要么说明方向判定把某条流算反了，要么 3477 那条根本不是游戏。
同样需要一份能解密的样本来定。
