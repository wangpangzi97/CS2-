## 0. 架构变更说明（本轮）

用户要求「改回本机，不使用上行到公网，按原版的方案」。本轮完成的重构：

| 项 | 改造前（远端方案） | 改造后（本机方案，当前） |
|---|---|---|
| 解码位置 | Linux 服务器 `109.206.245.172:8899` | **本机同一进程** |
| 雷达页 | `https://109.206.245.172:8899/radar`（需 token + 证书） | **`http://127.0.0.1:8766/radar`** |
| 数据流向 | 原始包 + 会话私钥 → 公网 | **不出本机** |
| 网络足迹 | 到公网 8899 的 HTTPS 长连接 | **仅 `127.0.0.1:8766` 监听，零对外连接** |
| 分发内容 | exe + json + **server.crt** + token | exe + json（**无证书、无 token**） |
| 与原版一致性 | 原版是本地页，我们偏了 | **对齐原版** |

实现方式：把服务端解码逻辑抽成可复用包 `internal/radarsrv`，
采集器在 `-uplink` 为空时**内嵌启动**这个包（本地 HTTP 服务 + 解码器），
`-uplink` 非空时才走远端。两种模式共用同一份解码代码。

## 1. 结论：已经做好，任意电脑可运行

`capture.exe` 是**静态链接**的 Windows amd64 单文件（6.86 MB），
不依赖 Go 环境、不依赖任何运行库（`CGO_ENABLED=0`），
拷到任何 Win10/11 x64 机器上双击即可。

运行它只需要**一样**外部条件（不是"环境"问题，是功能必需）：

| 条件 | 为什么必需 | 怎么满足 |
|---|---|---|
| 管理员权限 | 读 `cs2.exe` 进程内存、打开抓包句柄，Windows 都要求管理员 | `.bat` 会自动弹 UAC 提权 |

**Npcap 不是必需的。** 抓包有两个后端，`capture.json` 里 `"backend": "auto"` 自动选：

| 后端 | 要不要装东西 | 能力 |
|---|---|---|
| **raw socket** | **不用装**（Windows 内置） | 默认 `SIO_RCVALL` **双向抓包**；拿不到管理员时降级为只收方向 |
| Npcap | 要装内核驱动 | 双向抓包 + 可选网卡 |

> ⚠ 抓包**必须双向**：客户端握手包是客户端发出去的（发送方向），
> 只有它才带密钥搜索的靶子公钥。早期 raw 只用「只收方向」的 socket，
> 结果握手永远抓不到、雷达页一直空白（详见
> `report/raw方向问题与SIO_RCVALL修复.md`）。现已修好，仍无需装 Npcap。

所以：**不想装 Npcap 就什么都别装，直接双击「启动雷达.bat」。**
详细对比与实测证据见 `report/Npcap依赖与raw后端分析.md`。

**它必须跑在「正在玩 CS2 的那台电脑」上** —— 因为它抓的是本机网卡流量、
读的是本机 `cs2.exe` 的内存，解码也在本机。整条链路不联网。

## 2. 分发包内容

```
cs2radar-client/
├── capture.exe            采集器主程序（免安装，静态链接，内嵌解码器与雷达页）
├── capture.json           配置：监听地址 / 会话名 / 抓包后端 / 目标进程
├── 启动雷达.bat            正常入口（后端 auto：有 Npcap 用 Npcap，没有就 raw）
├── 启动雷达-免Npcap.bat    强制 raw socket，不装任何驱动
├── 仅抓包不读内存.bat      排障用，不碰游戏进程内存
├── 自检.bat               抓包能力自检 + 设备枚举
└── 使用说明.txt            完整流程（随包一起发）
```

`capture.json` 内容（本机模式，**没有服务器地址 / token / 证书**）：

```json
{
  "listen": "127.0.0.1:8766",
  "session": "room1",
  "backend": "auto",
  "proc": "cs2.exe"
}
```

生成脚本：`rebuild/cs2radar/tools/build_client_package.py`（可重复执行）

编码约定（踩过的坑，别改）：
- `.bat` → **GBK(936)、无 BOM**，文件头 `chcp 936`。cmd 只认 ANSI 代码页，
  用 UTF-8 存中文会乱码。
- `使用说明.txt` → **UTF-8 with BOM**，记事本能可靠识别中文。
- `capture.json` → **UTF-8 无 BOM**（Go 的 `encoding/json` 遇 BOM 会报错）。

## 3. 具体使用流程

### 3.1 首次准备（只做一次）

1. **解压整个文件夹**
   不要只把 `capture.exe` 单独拖出来 —— 它靠同目录的 `capture.json` 工作。

2. **（可选，不装也能跑）装 Npcap** —— <https://npcap.com/#download>
   安装向导里勾选：
   ```
   [x] Install Npcap in WinPcap API-compatible Mode
   ```
   装了 → 双向抓包 + 可选网卡；不装 → 自动走 raw socket。
   **不装不会报错**，`auto` 后端会静默回退。

### 3.2 每次使用（3 步）

```
① 双击「启动雷达.bat」
      ↓ UAC 弹窗 → 点「是」（脚本自动提权）
      ↓ 抓包能力自检通过 → 启动本机解码服务 → 自动用默认浏览器打开雷达页
② 启动 CS2，进入对局（进服务器后才会出现目标）
③ 保持那个黑色命令行窗口开着
      关闭窗口 = 停止采集；雷达页自己刷新，无需手动操作
```

脚本内部实际做的事：

```bat
cd /d "%~dp0"                          :: 提到自己所在目录（提权后 CWD 会变）
net session / fltmc  判定管理员 → 否则 PowerShell Start-Process -Verb RunAs 重新拉起自己
capture.exe -selfcheck                :: 真实打开一次抓包句柄做自检（Npcap / raw 都试）
capture.exe -open-browser %SESSARG%   :: 启动本机服务；服务监听成功后再开浏览器
```

> 浏览器由**程序自己**打开（`-open-browser`），不是 bat 里 `start` ——
> 早期版本 bat 先 `start` 再启动采集，页面会因服务尚未监听而打不开。
> 现在是 `net.Listen` 成功之后才调 `openBrowser`，时序正确。

> 早期版本这里用的是 `capture.exe -list-devices` 做预检，那会**把 Npcap 误判成硬依赖**
> （`-list-devices` 只枚举 Npcap 设备，缺 Npcap 就返回非零退出码）。
> 已改为 `-selfcheck`，它会真实打开一次抓包句柄，两个后端都试。

### 3.3 雷达画面

```
http://127.0.0.1:8766/radar?session=room1
```

- **本机回环地址**，只有这台电脑能访问；不需要 token、不需要证书、不需要联网。
- 页面每 500 ms 轮询 `/api/v1/radar`，显示各目标坐标与距离。
- 浏览器没自动打开的话，手动复制上面的地址粘贴进去。

### 3.4 换房间 / 多房间隔离

靠 `session` 区分，互不干扰。两种改法：

- **传参**（推荐）：`启动雷达.bat myroom` —— `.bat` 会把第一个参数
  透传给 `-session`，并且雷达链接也跟着换。
- **改配置**：编辑 `capture.json` 的 `"session"` 字段。
  改完记得雷达页面 URL 里的 `session=` 也要一致。

## 5. 排障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 bat 闪一下就没 | 没给管理员权限 / 杀软隔离了 exe | 右键 → 以管理员身份运行；先跑「自检.bat」看哪个后端可用 |
| `wpcap.dll not available` | Npcap 没装（**不是致命错误**） | 不用管，会自动走 raw；或双击「启动雷达-免Npcap.bat」 |
| 提示"当前不是管理员权限" | 直接从非提权终端运行 | 右键 bat → 以管理员身份运行 |
| 抓不到包 / 雷达页空白 | 网卡选错 / 链路不通 / 没权限 | ①跑「自检.bat」确认 raw socket 是否可用 ②浏览器开 `/health` 应返回 `ok:true` ③用「仅抓包不读内存.bat」隔离内存读取问题 ④装了 Npcap 且多网卡时把网卡名填进 `capture.json` 的 `"dev"` |
| 浏览器打不开页面 / 一直转圈 | 采集窗口被关了 | 重新双击 `启动雷达.bat`；确认地址是 `http://127.0.0.1:8766/radar` |
| 提示端口被占用 | 8766 被别的程序占了 | 改 `capture.json` 的 `"listen"`（如 `127.0.0.1:8767`），访问对应端口 |

## 6. 命令行参数（进阶，优先级高于 capture.json）

```
capture.exe -h                        全部参数
capture.exe -selfcheck                抓包能力自检（真实打开一次句柄）
capture.exe -list-devices             列抓包设备 + 后端可用性
capture.exe -print-radar-url          只打印雷达链接后退出
capture.exe -open-browser             本机模式启动后自动开浏览器
capture.exe -listen 127.0.0.1:8767    换雷达页监听地址
capture.exe -backend raw              强制 raw socket（不需要 Npcap）
capture.exe -backend npcap            强制 Npcap
capture.exe -session myroom           指定会话名
capture.exe -dev "\Device\NPF_{...}"  指定网卡（仅 Npcap）
capture.exe -duration 2h              跑 2 小时后自动停
capture.exe -hold 30s                 replay 后保持雷达页 N 秒（调试用）
capture.exe -no-keys                  只抓包不读内存
capture.exe -replay x.jsonl           离线重放（测试用）
capture.exe -config other.json        换配置文件
capture.exe -uplink https://...       改回远端服务器解码（默认空 = 本机）
```

优先级：**命令行显式参数 > capture.json > 内置默认值**
（实现上是在 `flag.Parse()` 之前把配置灌进 flag 默认值，
所以"命令行没给就用默认值"这条规则自然成立）。

## 7. 想改回「远端服务器解码」

本版本默认在本机解码。如果确实需要把「原始包 + 会话密钥」送到
另一台机器解码（例如机器性能不够），给 `capture.exe` 加 `-uplink`：

```
capture.exe -uplink https://<服务器>:8899/api/v1/ingest -token <密钥> -ca <证书>
```

服务端用 `cmd/radarserver`（薄封装，共用 `internal/radarsrv`）部署，
见 `report/工作流程与模块划分.md`。

> 注意：这条路会把会话私钥和原始抓包发到网络上，**默认不开**。
> 原版 v2.0.5 也是本机解码（它只把卡密发到 `154.12.82.177`），所以默认形态与原版一致。
