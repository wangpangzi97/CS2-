技术对比 · 游戏雷达

为什么三角洲能做成「纯软路由雷达」
而 CS2（完美）必须「主机读取」

同一件事，两种做法。差异不在技术高低，而在一个很朴素的问题：解密游戏流量所需的密钥，到底在哪里。

主题　网络层雷达 vs 内存层雷达 证据　CS2 侧为逆向实证 · 三角洲侧为公开资料与原理推断 日期　2026-10-13
结论先行

雷达能不能只靠网络层，只取决于一件事：
游戏的位置 / 状态数据，在网络层能不能被还原成明文？

能 → 抓包 + 协议解析即可 → 纯软路由雷达，游戏设备零足迹 —— 三角洲。
不能 → 必须进入游戏设备，读进程内存（或硬件 DMA）→ 主机读取 —— CS2 / 完美。

三角洲的网络数据包在网络层可解析，所以软路由够用。CS2 的客户端 ↔ 服务器通道是加密的，密钥每次连接临时协商、只存在于 cs2.exe 进程内存里，网络层抓到的是密文 —— 所以没有第二条路。

01先分清两条路线

所有雷达方案，本质上只有两个"落点"：网络层和内存层。

路线 A纯软路由雷达 · 网络层
游戏设备不装任何东西
→
软路由 / 网关转发 + 抓包 + 解析
→
游戏服务器
└─ 镜像解析出位置数据 → 展示端（手机 / 网页 / 第二屏）
路线 B主机读取雷达 · 内存层
游戏设备游戏 + 雷达进程
→
游戏服务器
└─ OpenProcess + ReadProcessMemory → 位置数据 / 会话密钥（可配合抓包解密）

路线 A 的关键是游戏设备零足迹；路线 B 的关键是能读到游戏进程的内存。两者不是替代关系，而是被游戏协议逼出来的不同选择。

02决定性变量：密钥在哪里

对比项三角洲CS2（完美）
网络层抓到的包可解析出位置密文
解密所需信息网络层可得（协议逆向即可）每会话临时协商的 X25519 私钥，只在进程内存
能否纯网络层能不能
可行路线软路由 / 内存 / DMA内存 / DMA

关键点：X25519 是椭圆曲线 Diffie-Hellman。服务器和客户端各自生成临时密钥对，交换公钥，各自算出同一个共享密钥。公钥在网络上是公开的，但 私钥在数学上无法从公钥反推 —— 这正是不对称加密的全部意义。

你在网络层能看到握手里的 公钥；
但你算不出 共享密钥；
而客户端进程内存里存着 私钥 —— 拿到它就能算出共享密钥，解密全部流量。
这就是「主机读取」存在的唯一理由

不是为了"读坐标方便"，而是因为网络层根本拿不到那把钥匙。

03三角洲为什么能纯软路由

在三角洲的雷达生态里，「软路由雷达」是一个成熟品类，原理被概括为「类 MITM + 数据包解析」，依赖抓包 + 协议逆向。

能这么做的前提是：位置同步数据在网络层可还原。可能是——

  • 协议明文；或
  • 加密但密钥静态 / 可推导；或
  • 只对部分字段加密

无论哪一种，结果都一样：软路由抓包 → 解析 → 出位置，全程不碰游戏进程。直接好处：

  • 游戏设备零足迹：手机上不装任何东西，反作弊在设备上扫不到可疑进程 / 模块 / 内存
  • 三端通用：手机、平板、PC 只要流量过软路由就能接
  • 多设备共享：一台软路由可以服务多台设备

04CS2（完美）为什么必须主机读取

CS2 是 Source 2 引擎，Valve 对客户端 ↔ 服务器的游戏通道做了加密（观战 / GOTV 数据更有独立的 tv_encryptdata_key / cl_decryptdata_key 密钥体系与 svc_EncryptedData 加密消息）。

我们逆向过一个真实在用的 CS2 雷达客户端（v2.0.5），它的行为把"为什么必须主机读取"写得很清楚：

  1. 定位 cs2.exe —— 250 ms 轮询找进程
  2. 只读打开 —— OpenProcess(pid, 0xC10)，即 VM_READ | QUERY_INFORMATION | SUSPEND_RESUME
  3. 枚举可读内存区域 —— VirtualQueryEx
  4. 暴力搜索 32 字节 X25519 私钥 —— 三条路径（缓存 hint / 锚点 anchor / 滑动窗口 window）+ 指针链遍历
  5. 校验候选 —— 用候选私钥推导公钥，和握手里抓到的公钥逐字节比对
  6. 命中后用私钥解密抓到的包 → 得到玩家位置

为什么非要这么绕？因为没有别的办法：

  • 网络层抓到的是密文
  • 密钥在进程内存里，而且每次连接都换
  • 所以只能：进入进程 → 拿密钥 → 回来解密
一句话

CS2 的主机读取，本质是为了「偷」那把只存在于内存里的会话密钥。

05两条路线的对抗面对比

维度纯软路由（网络层）主机读取（内存）
游戏设备足迹零有外部进程 + 句柄
前置条件流量可引导 + 协议可解密钥 / 数据在内存
对延迟的影响有（要过转发）无
反作弊能否在设备上发现基本不能用户态 AC 通常不能；内核级 AC 可以
部署复杂度需要额外硬件 / 主机装一个客户端
适用游戏网络层可解的游戏任何能读内存的游戏

一个反直觉的点

反作弊的强度，反过来决定了雷达形态的选择：

  • CS2 用 VAC（以用户态为主）→ 外部只读进程基本不被管 → 主机读取可行
  • 三角洲用 ACE（腾讯，带内核组件）→ 主机读取风险高 → 被逼向网络层

所以你会看到：同一个三角洲，既有软路由雷达，也有 DMA 雷达；而 CS2 的雷达几乎清一色是「内存读取 + 外部进程」。

06四个常见误区

误区 1 ·「软路由雷达更高级」

不是。这是协议决定的，不是技术高低。CS2 想做也做不了 —— 除非同时在主机上读内存。

误区 2 ·「主机读取 = 落后」

不是。CS2 只有这条路。而且"只读、不注入、不写内存"恰恰是它最安全的形态。

误区 3 ·「软路由雷达可以通吃所有游戏」

不能。只要会话密钥是临时协商且只在内存里（如 CS2），网络层就永远拿不到。

误区 4 ·「加密只是为了防作弊」

不完全是。CS2 加密游戏通道主要是防中间人 / 抓包篡改 / 网络层雷达 —— 这是一层独立于反作弊的防护。

07小结

问题答案
三角洲为什么能纯软路由？它的位置数据在网络层可解析
完美为什么必须主机读取？它的会话密钥每连接临时协商、只在进程内存，网络层只有密文
这是技术差距吗？不是，是协议设计差异
有没有第三条路？有，硬件 DMA（直接读物理内存），CS2 和三角洲都能用
雷达的形态不由「谁厉害」决定，由「密钥在哪里」决定。
密钥在网络上 → 软路由；密钥在内存里 → 主机读取。
