# 为什么三角洲能做成「纯软路由雷达」，而 CS2（完美）必须「主机读取」

> 一份关于游戏雷达两条技术路线的对比分析

---

## 结论先行

雷达能不能只靠网络层，只取决于**一件事**：

> **游戏的位置 / 状态数据，在网络层能不能被还原成明文？**

- **能** → 抓包 + 协议解析即可 → **纯软路由雷达**，游戏设备零足迹 —— 三角洲
- **不能** → 必须进入游戏设备，读进程内存（或硬件 DMA）→ **主机读取** —— CS2 / 完美

三角洲的网络数据包**在网络层可解析**，所以软路由够用。  
CS2 的客户端 ↔ 服务器通道是**加密**的，密钥每次连接临时协商、只存在于 `cs2.exe` 进程内存里，网络层抓到的是密文 —— 所以**没有第二条路**。

这不是技术高低，是**协议设计**决定的。

---

## 一、先分清两条路线

### 路线 A：纯软路由雷达（网络层）

```
[游戏设备] ──流量──> [软路由 / 网关] ──> [游戏服务器]
                          │
                          └─ 镜像 + 解析 ──> 位置数据 ──> 展示端（手机 / 网页）
```

- 游戏设备上**不装任何东西**
- 软路由 / 网关负责转发 + 抓包 + 协议解析
- 展示端可以是任何能上网的设备

### 路线 B：主机读取雷达（内存层）

```
[游戏设备：游戏 + 雷达进程] ──流量──> [游戏服务器]
        │
        └─ OpenProcess + ReadProcessMemory ──> 位置数据 / 会话密钥
```

- 必须在**跑游戏的那台机器上**运行一个外部进程
- 读游戏进程内存（或硬件 DMA 直接读物理内存）
- 常见做法：配合抓包，用内存里拿到的**密钥**解密网络包

---

## 二、决定性变量：密钥在哪里

|         | 三角洲            | CS2（完美）                       |
| ------- | -------------- | ----------------------------- |
| 网络层抓到的包 | **可解析出位置**     | **密文**                        |
| 解密所需信息  | 网络层可得（协议逆向即可）  | **每会话临时协商的 X25519 私钥，只在进程内存** |
| 能否纯网络层  | 能              | 不能                            |
| 可行路线    | 软路由 / 内存 / DMA | 内存 / DMA                      |

**关键点**：X25519 是椭圆曲线 Diffie-Hellman。服务器和客户端各自生成**临时密钥对**，交换**公钥**，各自算出同一个**共享密钥**。公钥在网络上是公开的，但**私钥在数学上无法从公钥反推** —— 这正是不对称加密的全部意义。

于是：

- 你在网络层能看到握手里的**公钥**
- 但你算不出**共享密钥**
- 而客户端进程内存里存着**私钥** → 拿到它就能算出共享密钥 → 解密全部流量

**这就是「主机读取」存在的唯一理由。**

---

## 三、三角洲为什么能纯软路由

> 本节基于公开资料与协议原理推断，非逐字节逆向实证。

三角洲的雷达生态里，「软路由雷达」是一个成熟品类，原理被概括&#x4E3A;**「类 MITM + 数据包解析」**，依赖**抓包 + 协议逆向**。

能这么做的**前提**是：位置同步数据在网络层**可还原**。可能是：

- 协议明文；或
- 加密但密钥**静态 / 可推导**；或
- 只对部分字段加密

无论哪一种，结果都一样：**软路由抓包 → 解析 → 出位置**，全程不碰游戏进程。

直接好处：

- **游戏设备零足迹**：手机上不装任何东西，反作弊在设备上扫不到可疑进程 / 模块 / 内存
- **三端通用**：手机、平板、PC 只要流量过软路由就能接
- **多设备共享**：一台软路由可以服务多台设备

## 四、CS2（完美）为什么必须主机读取

CS2 是 Source 2 引擎，Valve 对客户端 ↔ 服务器的游戏通道做了**加密**（观战 / GOTV 数据更有独立的 `tv_encryptdata_key` / `cl_decryptdata_key` 密钥体系与 `svc_EncryptedData` 加密消息）。

我们逆向过一个真实在用的 CS2 雷达客户端（v2.0.5），它的行为把「为什么必须主机读取」写得很清楚。

### 它做了什么

1. **定位 `cs2.exe`**：250 ms 轮询找进程
2. **只读打开**：`OpenProcess(pid, 0xC10)` —— `VM_READ | QUERY_INFORMATION | SUSPEND_RESUME`
3. **枚举可读内存区域**：`VirtualQueryEx`
4. **暴力搜索 32 字节 X25519 私钥**：三条路径（缓存 hint / 锚点 anchor / 滑动窗口 window）+ 指针链遍历
5. **校验候选**：用候选私钥推导公钥，和**握手里抓到的公钥**逐字节比对
6. **命中后用私钥解密抓到的包** → 得到玩家位置

### 为什么非要这么绕

因为**没有别的办法**：

- 网络层抓到的是密文
- 密钥在进程内存里，而且每次连接都换
- 所以只能：**进入进程 → 拿密钥 → 回来解密**

一句话：**CS2 的主机读取，本质是为了「偷」那把只存在于内存里的会话密钥。**

## 五、两条路线的对抗面对比

| 维度          | 纯软路由（网络层）    | 主机读取（内存）                               |
| ----------- | ------------ | -------------------------------------- |
| 游戏设备足迹      | **零**        | 有外部进程 + 句柄                             |
| 前置条件        | 流量可引导 + 协议可解 | 密钥 / 数据在内存                             |
| 对延迟的影响      | 有（要过转发）      | 无                                      |
| 反作弊能否在设备上发现 | **基本不能**     | 用户态 AC 通常不能；**内核级 AC 可以**（枚举句柄 / 挂起检测） |
| 部署复杂度       | 需要额外硬件 / 主机  | 装一个客户端                                 |
| 适用游戏        | 网络层可解的游戏     | 任何能读内存的游戏                              |

### 一个反直觉的点

**反作弊的强度，反过来决定了雷达形态的选择**：

- CS2 用 VAC（以用户态为主）→ 外部只读进程基本不被管 → **主机读取可行**
- 三角洲用 ACE（腾讯，带内核组件）→ 主机读取风险高 → **被逼向网络层**

所以你会看到：**同一个三角洲，既有软路由雷达，也有 DMA 雷达**；而 CS2 的雷达几乎清一色是「内存读取 + 外部进程」。

## 六、四个常见误区

1. **「软路由雷达更高级」**  
   不是。这是**协议决定的**，不是技术高低。CS2 想做也做不了 —— 除非同时在主机上读内存。
2. **「主机读取 = 落后」**  
   不是。CS2 只有这条路。而且「只读、不注入、不写内存」恰恰是它最安全的形态。
3. **「软路由雷达可以通吃所有游戏」**  
   不能。只要游戏的会话密钥是临时协商且只在内存里（如 CS2），网络层就永远拿不到。
4. **「加密只是为了防作弊」**  
   不完全是。CS2 加密游戏通道主要是防**中间人 / 抓包篡改 / 网络层雷达** —— 这是一层独立于反作弊的防护。

---

## 七、小结

| 问题           | 答案                                |
| ------------ | --------------------------------- |
| 三角洲为什么能纯软路由？ | 它的位置数据在**网络层可解析**                 |
| 完美为什么必须主机读取？ | 它的会话密钥**每连接临时协商、只在进程内存**，网络层只有密文  |
| 这是技术差距吗？     | 不是，是**协议设计差异**                    |
| 有没有第三条路？     | 有，**硬件 DMA**（直接读物理内存），CS2 和三角洲都能用 |

**一句话记住**：

> 雷达的形态不由「谁厉害」决定，由「密钥在哪里」决定。  
> **密钥在网络上 → 软路由；密钥在内存里 → 主机读取。**
