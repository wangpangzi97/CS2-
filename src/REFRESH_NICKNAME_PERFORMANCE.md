# 第五次更新：100ms刷新、昵称显示与检查点性能
2026-10-21。后文为历史说明，本节说明当前交付。

1. tick采用单请求串行轮询，目标起始间隔100ms；响应超过100ms时等待该请求完成，不重叠堆积。5秒超时可恢复，退出页面终止请求。
2. 接收快照与requestAnimationFrame绘制分离。可选最多60ms追随平滑，不外推；死亡、重生、换队、旧位置、换图和大位移不跨状态插值。追求最低显示等待可关闭“平滑移动”。
3. 默认显示昵称，空昵称退回编号。支持显示开关、4–32字最大长度（默认12），按Unicode字素截断；重名和截断后撞名均加[#编号]区分；昵称始终按文本输出。浏览器保存设置，有恢复默认按钮。
4. 新增固定大小耗时直方图：批次最老排队/交付/锁等待，Ingest/Process，实体包/恢复/应用/检查点/快照。API performance和[perf]运行日志可查；p50/p95为桶上界，非精确分位数。
5. 实测主要开销为检查点深拷贝。检查点改为冻结共享、实体字段写入前按需分离，并保留字段容量、预算、精确delta_from恢复和原内存上限。只减少不必要复制，不丢原始包或取消实体校验。

7. 本地64包/200ms批策略保留；实测稀疏单包约200ms交付、满64包提前交付。瓶颈测量和优化集中在检查点复制，避免盲目增加解码批次。
