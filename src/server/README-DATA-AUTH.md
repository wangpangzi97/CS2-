# 设备授权与像素视图候选：未部署，不能直接替换正式客户端

本候选已实现设备授权、白名单像素视图和原生回环界面桥接。
只有持有效签名的 `GET /api/v1/radar` 返回当前授权会话的绘图 DTO；
远端 `/radar` HTML、旧诊断和会话枚举仍拒绝，绝不恢复原始 Snapshot 或静态 token。
本目录不包含管理员凭据、卡密或真实应用秘密；生产 HTTP 集成、敏感诊断收敛、
负载/最小权限与发布签名尚未验收，不能仅因本机测试通过就覆盖正式版。

## 实际信任链

1. 原生客户端先加载独立、按服务器/应用分区的 DPAPI Ed25519 密钥；损坏时拒绝，
   不静默换钥，再沿用 GuYi v2 HTTPS 激活，获取短 GuYi 会话。
2. 已登记公钥的卡密，其 GuYi 激活、心跳和解绑也须提交相同设备的持钥证明。
   不能只靠卡密/设备哈希重新激活后走旧解绑接口来清除公钥登记；管理员重置例外。
3. 登录 challenge 60 秒一次性消费；原生端对明确版本的规范文本同时提供
   Ed25519 签名及 GuYi 会话派生 HMAC。卡密、GuYi 会话密钥不发送给数据代理。
4. 固定 PHP CLI 适配器读取现有 GuYi 配置/数据库，验证该 HMAC 和卡密状态，
   持久化卡密/设备的公钥登记。没有服务器端重置，不接受换公钥。
5. 数据会话绝对上限 12 小时且不超过卡密到期；256 位随机数据资格 120 秒，
   每 30 秒持钥心跳轮换资格，活动租约 90 秒。没有独立的长效 Bearer 刷新通道。
6. 每个请求签名覆盖版本、固定 HTTPS audience、方法、路径、资格哈希、时间戳、
   随机 nonce、实际请求体哈希；不是 OAuth/DPoP 实现，不应冒用其兼容名称。
7. 业务请求前查验会话归属、签名、重放和有效权益；GuYi 正结果最多缓存 2 秒。
   后端异常拒绝并撤销当前会话；过期/断连会话定期清理，不宣称安全擦除 Go 内存。

## 服务端安装前置条件（本轮没有执行）

- 先备份并评审 `guyi-patch/app/Infrastructure/Database/Database.php`、
  `guyi-patch/app/Api/VerifyV2.php` 和新增 `guyi-patch/app/Security/DeviceProof.php`
  相对现有 hardened GuYi 的差异，再由有迁移权限的账号执行
  `guyi-patch/data-auth-migration.sql`。迁移在本机 MariaDB/InnoDB 夹具验证；
  其他数据库版本需先验证 DDL 兼容性，不能直接假定支持 `ADD COLUMN IF NOT EXISTS`。
  Web/代理账号继续仅具有必要 CRUD 权限，不授予 DDL，不开放数据库公网端口。
- 安装上述三份 PHP 补丁并确保 Web PHP 与 CLI 都启用 sodium。缺少验签扩展时拒绝，
  不允许跳过设备证明；未登记卡密只允许首次登记，旧版客户端在登记后不再兼容。
- 补丁为卡密增加 `data_epoch`，在踢线/封禁/解封/解绑时推进；备份恢复清除公钥登记。
  随机 binding ID 防止旧会话因恢复同一数字代次而复活。旧卡密、应用秘密不重写。
- `radarserver` 必填受信绝对路径 `-php-binary`、`-authority-script`、`-guyi-project`，
  以及 `-app-id`、`-public-origin`。启动检查数据库字段、API 设备证明守卫、
  sodium 和后端补丁版本，缺任何一项拒绝。
- 公网入口必须 HTTPS。仅在显式 `-trust-loopback-proxy` 且仅监听回环时允许内层 HTTP；
  nginx 必须覆盖 `X-GS-TLS: 1` 和 `X-GS-Client-IP: $remote_addr`，不能拼接客户端头。
  `X-Forwarded-For` 不作为身份依据。既有 IP HTTPS 证书和续期机制保持不变。
- 服务器路径/解释器/配置仅管理员可写；CLI 不经过 shell，输入输出有界并有超时。
  不把任何服务器配置复制进客户端包。当前仅支持单数据服务实例，重启使旧资格失效；
  横向扩容前必须设计共享重放/撤销状态，不能直接负载均衡多个进程。

## 客户端与兼容性

GUI 的打开按钮和 `-open-browser` 打开原生进程创建的 `http://127.0.0.1:随机端口/radar`。
这是仅限回环的界面，不是公开 HTTP 数据 API；远端仍严格要求 HTTPS。
授权完成后也可以用 `capture.exe -config capture.json -view-only -open-browser`
只查看远端画面：不提权、不开采集口、不访问游戏进程。需事先安装匹配服务端与公开配置。
旧 `-print-radar-url` 不能在授权前给出可用视图地址，现在明确报错，不再推荐远端 HTML。

`viewframe` 是独立共享契约：版本、随机 generation、画布尺寸、地图/静态图片路径、
两个像素点列表。每个点只有 `id/px/py`；没有世界坐标/Z、实体索引/serial、姓名/SteamID、
队伍/血量、密钥材料、解码方案或性能诊断。声音是灰圈，不冒充人物；人物未同步时为空。
未知地图不做世界范围自适应缩放，直接不返回点。地图投影只在服务端执行并取整。
像素可结合已知地图近似反算；这是减小暴露面，不是不可逆加密或反转发保证。

随机 ID 使用独立 128 位熵，不是实体编号哈希。玩家按现有 ID/pawn/serial 私下关联，
声音按可见发声源关联；同会话可见期间稳定，消失后观察到再出现则换 ID。
换图、signon/reset、撤销/退出与新数据会话清空关联，界面按 generation 清轨迹与底图。

原生桥接每 250ms 拉取一次签名视图；网页轮询只读本机缓存，不可控制远端目标/会话。
原生在消费上游响应时再次执行严格 JSON 白名单、数量/像素范围/资源路径校验。
仅绑定 IPv4 回环；校验精确 Host、同源浏览器元数据、HttpOnly/SameSite=Strict 随机 Cookie，
POST 还校验 Origin 与 JSON。无 CORS、无任意代理，页面 CSP 禁止外部脚本/连接。
首次 Cookie 仅由顶层直接导航初始化；不支持 Fetch Metadata 的浏览器失败关闭。
这些限制防网页跨源访问，不防能伪造 HTTP 头的本地 OS 进程；不能夸大成本机强隔离。
设备私钥/远端资格不进入网页或 URL。本地 HTTP Cookie 不是远端资格，也不由 JS 读取。
缓存超过 1 秒不能提供画面；上游失败、异常 DTO 或授权撤销立即使桥接失效并清缓存。
网页还根据剩余有效时间独立清屏；隐藏页面/切图也清轨迹，不保存离线位置。

正式入口不再接受 `-token`、`-session` 或配置中的非空旧 token/自选会话。
会话由服务器分配，上行不能自行选择其他用户的 Store。仍强制 HTTPS、验证证书和身份，
禁止跳转、查询参数凭据、HTTP 或跳过证书校验。
IP 前缀变化触发重新认证（IPv4 /24、IPv6 /56），不是永久封卡或硬件身份凭据。
设备私钥属于用户控制的操作系统；DPAPI/指纹/签名不能证明程序未被修改，也不能阻止
合法持卡者转发输出，或抹除已泄露的旧版本本地能力。
